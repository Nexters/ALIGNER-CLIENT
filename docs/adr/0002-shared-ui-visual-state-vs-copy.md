# ADR-0002. shared/ui 컴포넌트의 책임 경계 — 시각 상태 vs 문구

- 상태: 결정됨
- 날짜: 2026-08-13
- 맥락 소유: `shared/ui`

## 맥락

`ProgressRingItem`(원형 진행 링 아이템)과 `SequenceItem`(순번 레일 + 카드)을 같이 설계하면서, 두 컴포넌트가 서로 반대 방향으로 흘러갈 뻔했다.

- `ProgressRingItem`은 `current`/`total`을 받으니 배지 문구(`"1/4"`, `"완성"`)를 컴포넌트가 직접 만들 수 있다.
- `SequenceItem`은 `"1세트/2분"`, `"6kcal"`처럼 이미 조립된 문자열을 받는 편이 자연스럽다.

같은 레이어에서 한쪽은 한국어 카피를 내장하고 한쪽은 안 하면, 이후 추가되는 공통 컴포넌트마다 매번 같은 논쟁이 반복된다. 특히 `"완성"` 같은 카피가 `shared/ui`에 박히면 문구 하나 바꾸려고 공통 컴포넌트를 건드려야 한다.

## 결정

**`shared/ui` 컴포넌트는 숫자·불리언으로 시각 상태를 결정하고, 사람이 읽는 문자열은 전부 외부에서 주입받는다.**

- 시각 상태를 결정하는 값(비율, 개수, 활성 여부, 순번)은 prop으로 받아 컴포넌트가 소유한다. 이건 기하·상태 정보지 카피가 아니다.
  - 예: `ProgressRingItem`의 `current`/`total`은 아크를 그리려면 숫자여야 하므로 남긴다.
- 화면에 그대로 출력되는 문자열은 컴포넌트가 만들지 않는다. 포맷·번역·도메인 표현은 쓰는 쪽(feature/page)이 책임진다.
  - 예: `badgeLabel="완성"`, `descriptions={["가동성 웜업", "1세트/2분"]}`, `caption="6kcal"`.
- 아이콘처럼 문자열이 아닌 장식 요소는 슬롯(`ReactNode` prop)으로 열어 쓰는 쪽이 넣는다. 공통 컴포넌트가 특정 아이콘을 하드코딩하지 않는다. (ADR-0001의 composition 원칙과 같은 방향)

### 토큰 우선 원칙

Figma 값이 `styles/tokens/`의 타이포 토큰과 어긋나면 **토큰을 따른다.** 한 컴포넌트를 픽셀 단위로 맞추려고 토큰 밖 임의값을 쓰기 시작하면 디자인시스템이 무의미해진다.

- 실제 사례: `SequenceItem` 카드의 Figma 텍스트는 `line-height: 24px` 고정이지만, 토큰은 전부 `1.4`다. 토큰(`typo-body-emphasized`, `typo-subheadline-regular`)을 쓴다.
- 색·radius·간격처럼 토큰에 대응이 없는 치수는 ADR-0001대로 rem 임의값을 쓴다.

## 결과

- 공통 컴포넌트에 한국어 카피가 남지 않는다. 문구 변경이 `shared/ui`를 건드리지 않는다.
- 대신 쓰는 쪽이 `"완성"`/`"1/4"` 분기를 직접 써야 한다. 같은 분기가 여러 feature에서 반복되면 그때 해당 feature 안의 헬퍼로 뽑는다 — `shared/ui`로 되돌리지 않는다.
- 토큰과 Figma가 어긋나는 지점은 발견될 때마다 `docs/design/design-system.md`에 기록한다.
